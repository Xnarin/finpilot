# 회고: 핵심 고민과 해결

2026-10-19. 지금까지의 고민 중 방향을 바꾼 것만 추렸다. 정리는 Claude가 했고 사용자 검토 전이다. 상세 근거는 [index.md](index.md)의 문서들에 있다.

## 1. 숫자가 맞는다는 걸 어떻게 믿나
- **고민:** 가상 데이터에서 실제 OpenDART 조회로 바꿨을 때, 화면 숫자를 믿어도 되는가.
- **해결:** 계정은 ID로 정확히 한 건만 고르고(0건·2건 이상이면 오류), 연결이 없다고 별도로 대체하지 않는다. 삼성전자·SK하이닉스·현대자동차 2022~2025를 사용자가 DART 원문과 직접 대조했고, 그 값을 실제 호출 회귀 테스트로 고정했다.
- **남은 것:** 현대자동차 2022의 접수번호가 2024년 3월 접수분이다. 정정 보고서가 조회되는 것으로 보이나 미확인이고, 정정공시를 어떻게 다룰지 정하지 않았다.

## 2. 점수가 높다고 믿어도 되나
- **고민:** 쉬운 질문에서 잘 맞는 것이 실제 사용자 질문에서도 맞는다는 보장이 없다.
- **해결:** 질문을 114개로 늘렸다(오타, 구어체, 딴소리, 짓궂은 질문 포함). 같은 질문을 3회 반복했고 오답을 위험 / 과잉 거절 / 무해로 나눴다. 기준선 태그를 남겨 이후 비교의 출발점으로 삼았다.
- **얻은 것:** 같은 질문의 결과가 매번 다르다(temperature 0에서도). 점수가 높은 묶음에서도 분기·별도 기준을 연간 값으로 조용히 답하는 위험 오답이 드러났다.

## 3. 답하지 못한 질문을 어떻게 다룰까
- **고민:** 못 푼 질문을 버리지 않고 나중에 도구·에이전트로 풀고 싶다.
- **해결:** 64문항을 원인별 6유형으로 묶어 백로그와 JSON으로 저장했다. 복수 연도·회사 같은 앞으로의 요구와 예외 상황도 golden set 후보로 기록했다.

## 4. 에이전트를 어떻게 만들까
- **고민:** 복수 연도·회사가 올 텐데, 구조화 출력과 도구 호출 중 어떻게 설계하나.
- **해결:** 연도는 "값"이 아니라 "표현"으로 받아 코드가 계산하는 안, 그리고 도구 호출 에이전트를 비교했다. "랭체인으로 에이전트를 만들 건데 굳이 중간 단계를 거치는 이유"라는 지적이 맞아서, 별도 단계 없이 도구 함수 정의부터 에이전트로 가기로 했다. 지금의 단일 요청 파이프라인이 곧 비교 기준선이다.
- **남은 것:** 상대 연도 기준, 일부만 불확실한 복수 요청 처리 정책이 미정이다.

## 5. 회사명을 못 찾을 때
- **고민 1, LLM이 별칭을 알아서 원래 이름으로 바꿀 수 있나:** 시험하니 잘 맞혔지만(20/22) 자신 있게 틀린 사례가 있었다. **AI가 제안하고, 코드가 상장사 목록과 대조하고, 사용자가 확인한다**("처음엔 되묻기").
- **고민 2, 해외 기업은 한국어로 변환하면 검색이 안 되니 번역을 거쳐야 하나:** 원인은 번역이 아니라 글자가 비슷하기만 해도 후보로 내던 규칙이었고, OpenDART에는 해외 기업이 애초에 없다. 번역이 아니라 **AI가 한국 상장사 / 해외 / 비상장을 분류**해서, 해외·비상장이면 엉뚱한 후보를 버리고 "조회할 수 없다"고 안내하게 했다. 한국 상장사가 해외로 오분류된 경우는 평가에서 0건이었다.
- **고민 3, 유명 대기업은 약칭·초성이어도 바로 검색되면 좋겠다:** 처음엔 되묻기를 유지하되 **누구나 쓰고 하나로만 해석되는 유명 별칭 사전**(삼전·하닉·닉스·네이버 등)은 바로 확정하게 바꿨다. 대상이 목록에 정확히 한 곳일 때만, 초성은 다른 회사와 겹치지 않을 때만 확정하고, 화면에 "입력 → 해석"을 보여 준다. 평가에서 오확정은 0건이었다.
- **확인된 범위:** 한국 공시만 나온다. 해외 기업은 별도 데이터 출처가 필요한 확장 과제다.

## 6. 일부러 미룬 것
분기·별도 기준 문제는 도구 단계에서 풀기로 했다. 결정: **별도는 지원, 분기·반기·월은 "지원하지 않는다"고 안내하고 조용히 연간 값을 내보내지 않는다.** 분기 조회와 분기 비교는 MVP 이후 과제로 뺐다(분기는 값 하나보다 전분기·전년 동기 비교에서 투자 가치가 나오기 때문).

## 7. 도구를 정의하며 정한 것
- **날짜는 오늘 기준, 불확실하면 챗봇처럼 되묻는다.** "올해"는 아직 연간 보고서가 없으니 "공시 전"이라고 안내한다.
- **정정공시는 최신본을 쓴다.** 확인해 보니 정정은 흔했고(카카오 2023은 접수 4건), 조회는 이미 최신 정정본을 주고 있었다. 접수번호·접수일·정정 여부만 화면에 표시한다.
- **같은 이름의 회사 문제:** 상장폐지된 옛 법인과 이름이 같아 삼성물산이 조회되지 않았다. 기업개황의 상장 구분으로 현재 상장된 곳이 하나일 때만 확정하게 했다.
